# 05 — PROTOCOLE DE RECHERCHE WEB

# 1. Le web a trois rôles distincts

## A. Vérification
Vérifier un fait.

## B. Exploration
Découvrir une information / hypothèse oubliée.

## C. Forward research
Comprendre ce que le marché attend et ce qui peut se passer ensuite.

Ces rôles doivent être distingués.

---

# 2. Le web n’est pas un vote

Ne jamais faire :

« la majorité des articles disent bullish donc bullish ».

La masse peut avoir raison.

La masse peut avoir tort.

L’edge peut parfois venir d’un angle minoritaire.

La valeur d’une opinion dépend de :

- qualité de l’argument ;
- accès à l’information ;
- expertise ;
- cohérence avec les faits ;
- indépendance ;
- fraîcheur ;
- définition ;
- biais éventuel.

---

# 3. Multilingue

La recherche ne doit pas être limitée à l’anglais si une autre langue peut apporter une information pertinente.

Elle peut explorer :

- anglais ;
- français ;
- chinois ;
- japonais ;
- arabe ;
- russe ;
- autres langues utiles.

Mais :

plus de langues ≠ plus de vérité.

Le classement des sources reste basé sur la qualité, pas la langue.

---

# 4. Univers de sources

Selon le besoin :

### Sources primaires
- organismes officiels ;
- banques centrales ;
- Treasury ;
- exchanges ;
- issuers ;
- CFTC ;
- etc.

### Wires / presse financière
- pour breaking news ;
- attribution ;
- narratives ;
- réactions de marché.

### Desks / stratégistes / analystes
- mécanismes ;
- scénarios ;
- consensus ;
- contrarian views ;
- forward risks.

### Forums / X / communautés de traders
- angles négligés ;
- observations ;
- microstructure ;
- alternative hypotheses.

Ces dernières sources ne deviennent jamais un FACT uniquement parce qu’elles paraissent intelligentes.

---

# 5. Vérifier l’auteur lorsque l’opinion devient importante

Si une opinion externe influence réellement la thèse :

- qui est l’auteur ?
- quel rôle ?
- quel historique / background public ?
- parle-t-il de son domaine ?
- cite-t-il des données ?
- est-il original ou répète-t-il un wire ?
- quelle date ?

Le background ne prouve pas qu’il a raison.

Mais il aide à pondérer l’opinion.

---

# 6. La bonne question web

Éviter :

« Gold outlook today »

Préférer :

- quelle donnée officielle confirme ce chiffre ?
- qu’est-ce que le marché price actuellement pour la prochaine réunion ?
- quel est le prochain catalyst qui peut modifier cette thèse ?
- quelles lectures alternatives expliquent cette divergence ?
- quelle composante du release a dominé le repricing ?
- quelles contraintes de positioning sont documentées ?
- existe-t-il un événement non présent dans notre calendrier ?
- quels desks voient un risque que notre première lecture oublie ?
- quelles raisons soutiennent le scénario adverse ?

---

# 7. Le web doit enrichir, pas dicter

Processus :

1. l’IA construit sa première lecture à partir des données vérifiées ;
2. elle note ce qu’elle ne comprend pas ;
3. elle cherche sur le web ;
4. elle collecte nouveaux faits, hypothèses et opinions ;
5. elle les fait repasser dans le framework ;
6. elle peut :
   - garder sa thèse ;
   - la nuancer ;
   - l’abandonner ;
   - ajouter un scénario ;
   - reconnaître qu’elle ne peut pas trancher.

---

# 8. Chaque idée externe doit subir les mêmes filtres

Pour une idée web :

1. quel fait la soutient ?
2. quelle chaîne causale ?
3. quel timing ?
4. est-ce déjà pricé ?
5. quelle contradiction ?
6. quel scenario adverse ?
7. qu’est-ce qui la falsifie ?
8. apporte-t-elle vraiment une information nouvelle ?

---

# 9. Le web final

Après la confrontation des IA, une dernière exploration web doit exister.

But :

- vérifier qu’aucun catalyst récent n’a été manqué ;
- détecter une information apparue pendant l’analyse ;
- chercher une objection de haute qualité ;
- vérifier la fraîcheur ;
- enrichir les scénarios futurs ;
- détecter ce qui est déjà pricé ;
- détecter un changement de narrative.

Cette dernière passe ne doit pas automatiquement rouvrir tout le raisonnement.

Elle met à jour uniquement si l’élément est matériel.
